## Global Constraints

- "ENGINE_API_VERSION=0.2.0, NET_PROTOCOL_VERSION=2"; base/acme/haul package version 0.2.0, engine_api='^0.2'.
- "No silent v0.1 defaults or save migration."
- "Author-facing package and wire references are quoted qualified strings, as in M1."
- "Complete registration and map validation occur in a staging registry/world before any live registry, amount, entity or id allocator changes."
- "Balances, node remainder, on-hand items, reserved amounts, charged costs, refund totals and job progress use u64."
- "Capacity sums and all intermediate multiply/add operations use checked u128, then checked conversion to u64."
- "Tick (u32), UnitId/NodeId (u32) and JobId (u64) allocations are checked and never reused"; tick exhaustion stops the match before wrap.
- "Every Balance resource creates a zero account for every configured slot at boot; no Balance definitions means no accounts."
- "Producers are static in M2"; output is exactly one mobile unit without producer capability.
- "A Store receiver whose inventory is the cargo source is ineligible"; cargo is retained when delivery cannot proceed.
- "A newly started job has progress zero; first advancement is next tick."
- "No created UnitId, output entity or completion event until the spawn commits."
- "Filter before serialization by receiving Session.slot, for both snapshots and deltas."
- "Coalesce recovery behind the outstanding ResyncRequest; never issue another while that response is pending."
- "Use the same Rust client logic native and wasm"; this plan selects the design's permitted shared Bevy UI option.
- "M2 supplies no interpreter, guest executable, package event handlers, registered callbacks, hooks per entity/item/tick, runtime subscription API or arbitrary closure execution."
- Preserve forbidden edges in `CLAUDE.md` and `scripts/boundary.sh`; neither public schema nor wire types contain Bevy types. Clients never depend on `turts_sim`.
- Fixture rates, sizes, 20 Hz and 2,000 simulated-tick deadlines establish correctness only. Repeat rate/duration/rounding at 10 and 30 Hz. No new VM, capacity claim, runtime choice, destruction policy, or performance threshold.

## Shared type decisions

These names resolve implementation choices left to the builder, without changing gameplay rules.

- Keep `turts_mod_api::ContentId` internal struct serialization unchanged; never put it directly into authored/wire fields. Public `ContentRef = String`. `ContentCatalog` owns typed `BTreeMap<ContentId, ...>` entries after validation; serialized schema remains exactly design §3. `SourceDef<T> { file: String, def: T }` preserves diagnostic provenance.
- `ContentCatalog { origin: PackageId, resources, units, nodes, production }` uses resolved entry types `ResourceType`, `UnitType`, `NodeType`, `ProductionType`; their semantic fields match the corresponding definitions, with each ContentRef resolved to ContentId. No Bevy dependency. `UnitTypes` retains dense `UnitTypeId` lookup for M1 internals and projects from this catalog.
- Simulation ids remain distinct from wire ids: existing `turts_sim::UnitId(pub u32)`, new `NodeId(pub u32)` and `JobId(pub u64)` in `turts_sim/src/ids.rs`; protocol has its own equivalent newtypes. Only `turts_server::export`/command translation converts `.0` values. `SlotId` remains each crate's existing wrapper. Geometry converts `WorldPos`/`Pos` to `Vec2` at these boundaries only.
- `Account`, `Inventory`, `Endpoint`, `ReservationLine`, `Reservation`, `ProductionJob` and `JobStage` follow design §4. Put them in `economy/ledger.rs` and `economy/production.rs`. `EconomyLedger` is one Resource holding accounts/inventories/reservations; components link entities by stable id. No second mutable account copy lives on entities.
- `BalanceView`, `InventoryView`, `NodeView`, `QueueView`, `OrderView` are owned Clone/PartialEq data, never mutable references. Public view getters in Task 3 return `Result<View, RejectReason>` and validate requested slot ownership before private details.
- `Command { slot: SlotId, seq: u32, kind: CommandKind }` keeps its M1 shape. `CommandKind` adds `Gather { unit_id: u32, node_id: NodeId }`, `Produce { producer_id: u32, recipe_id: ContentId }`, `CancelProduction { producer_id: u32, job_id: JobId }`. `CommandResult.outcome` becomes `Result<Applied, RejectReason>`, where `Applied { job_id: Option<JobId> }`.
- `CommittedTick { tick: u32, spawned: Vec<UnitState>, removed: Vec<u32>, positions: Vec<(u32, Vec2)>, nodes: Vec<NodeView>, economy: EconomyChangesView, events: Vec<EconomyEvent> }` is immutable after FixedPostUpdate. `EconomyChangesView` carries absolute replacement records with owner slots, not wire serialization. Snapshots read a completed-tick `WorldView`, not a mutable ECS query during command drain.
- `WorldView { tick: u32, units: Vec<UnitState>, nodes: Vec<NodeView>, economy: EconomyStateView }`. `EconomyStateView` and `EconomyChangesView` each contain `balances: Vec<BalanceView>, inventories: Vec<InventoryView>, orders: Vec<OrderView>, queues: Vec<QueueView>`. Each private record includes `owner_slot: u8`; balances add `resource: ContentId, on_hand: u64, reserved: u64`; inventories add `unit: u32, capacity: u64, items: Vec<ResourceAmountView>`; `ResourceAmountView` has `resource: ContentId, on_hand: u64, reserved: u64`. Node/order/queue/job view fields follow the exact design §7 records, with ContentId/internal ids instead of serialized strings/wire wrappers. Add no hidden pooled total. Snapshot and change views differ only by whether every record or changed replacement records are included.
- Diagnostic `AuditState` captures tick, all public units/nodes, all ledger accounts/inventories, all orders/queues/reservation lines and next allocator values. `audit_state(&mut World) -> AuditState` is a trusted Rust diagnostic, not an admitted player query. Its JSON form uses vectors of records, so JSON never needs ContentId map keys. Production replication never serializes AuditState.
- Public engine facilities use `&mut World` exclusive systems for atomic operations. Private `Transaction` has no public field or caller-created arbitrary credit/debit write set. Validated named operations build its complete write set, preflight it, then synchronously commit ledger/ECS/ids/events together.
