What is in the current game

  • Castle, Barracks, Villager, Crossbowman, Swordsman, trees, and textured ground.
  • Construction, harvesting for credits, training, combat, and automatic targeting.
  • Server-owned Victory, Defeat, or Draw, plus New skirmish.
  • A simple computer opponent. Its first attack starts after three minutes. It defends earlier.
  • Producer exit search and rally movement. Recruits no longer fill four exits and stop production.
  • Pointer-centred zoom with useful intermediate distances.

What the latest builds added

  • A full normal-stat scripted game wins in 132 seconds. An idle player loses in 217 seconds. New skirmish works after both results.
  • Gzip cuts the actual WASM transfer from 59.7 MB to 14.8 MB. Decoded game code stays identical.
  • A minimap shows both teams, resources, the camera frame, and short attack pings. Click or drag to look; right-click to send selected units.
  • Barracks offer Crossbowmen and Swordsmen. Swordsmen have 300 health, train in six seconds, and cost 80 credits.
  • Melee reaches the edge of a castle footprint. Mixed armies keep their separate weapon ranges.
  • Units walk, work, aim, shoot, and fall. Construction rises from the ground.
  • Bolts travel to their targets. Hits have sparks and a short white flash.
  • Damaged buildings smoke and burn. Destroyed castles leave debris and a scorch.
  • Offscreen attacks give text and a directional pulse. Press J or click the warning to jump there.
  • High and Low give the same server result. Low retains readable shots when its particle pool is full.
  • The scripted player probes pass at 1280 and 1024 pixels. Arrow keys pan quickly; edge targets stay still for a click.

The larger goal

Many RTS games through one public mod API

A mod should express the player-facing mechanics of StarCraft, Warcraft, Command & Conquer, Age of Empires, Supreme Commander, and industrial RTS games. These are capability references. TuRTS uses original content.

Game packages

Units, economies, recipes, maps, rules, art, HUD layout, and later portable scripts.

→

Versioned public API

Reusable engine capabilities. No Bevy internals in mod contracts. No private privileges for the default game.

→

Engine and clients

The headless server decides gameplay. Browser and native clients send commands and show permitted results.

Architecture that must stay sound

  • The server validates orders and owns match state.
  • Simulation, network records, and visual objects stay separate.
  • Animation, effects, and graphics quality never change match results.
  • Mods describe content. The engine draws it and controls cost.
  • New API fields are additive. Older packages continue to load.
  • Large repeated work runs in Rust, not a script for each unit each frame.

Long-term capabilities

Combat and abilities. Construction and research. Traditional resources and factory logistics. Editable terrain and buried deposits. Underground utility networks. Discovery and fog. Human and bot players. Rooms, identities, saves, replays, spectators, and large armies.

Terrain uses a heightfield with one surface height per location. Tunnels, caves, and navigable stacked ground are excluded. Scale targets remain ambitions until measured.

The current medieval skirmish is a deliberate short route to play. It does not complete the older C&C-style roster or every MP1 requirement.

What is not proved yet

Large battles with effects and AI together. Fog secrecy. Internet hosting capacity. Thousands of spectators. Full MP1 or MP2 acceptance. Final production artwork. Broad browser and minimum-hardware support.

The final model delivery did not repeat every older browser gate or the complete old manual-agent cold-play procedure. The required scripted probes did pass.

How we should work

Build as fast as possible without compromising quality. Each delivery must improve play. Use one code-running review per feature/spec. Protect authority, wire compatibility, determinism, and the mod API. Do not rebuild old process machinery.

Run test browsers with a fresh profile and --alsa-output-device=null. Keep evidence. Remove finished build caches. Merge or push main only with your explicit authorization.
