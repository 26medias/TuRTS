## CI proof contract

`.github/workflows/ci.yml` now declares two independent lanes. The native `check` lane runs, in order, `cargo fmt --all --check`, strict locked workspace Clippy, locked wasm check, locked workspace tests, `bash scripts/boundary.sh`, `bash scripts/m2-refutations.sh --case ci-native`, and unconditional `bash scripts/acceptance.sh`. The `browser` lane installs Node 20 and pinned `tests/browser` npm dependencies, Bevy native libraries, Brotli, Xvfb and software Vulkan; it runs `node --test tests/browser/m2-projection.test.js`, `bash scripts/t7.sh`, `bash scripts/m2-browser.sh`, then `bash scripts/m2-refutations.sh --case ci-browser`.

Both jobs upload diagnostics with `if: always()` and `if-no-files-found: warn`, including JSON/JSONL, PNG screenshots, manifests, logs and text records. Acceptance test records written under Cargo’s `CARGO_TARGET_TMPDIR` are collected from `target/tmp/**`. Browser run artifacts are rooted at `target/m2-browser/runs`; native and browser refutation evidence/build roots are separate under `target/m2-refutations`. The browser runner's no-argument all-four-package contract (base, haul, acme, cedar), private Xvfb display, Vulkan Chrome arguments, and Playwright default-argument override are agreed interfaces, but are **pending implementation and validation** in their owning lane. The refutation registry's `rust|browser` runtime plus `ci-native`/`ci-browser` selectors are also pending implementation and validation. Therefore this workflow is an integration target, not evidence that those commands currently pass. The CI workflow itself has not been run on GitHub yet.

Task16 browser CI uses software Vulkan where needed; it does not require an NVIDIA GPU. Hosted runner backend/device identity, tool versions, artifact hashes, and test outcomes must be collected from actual run artifacts before reporting CI measurements.
