## For future Claude
How the daily report works. One note per day, `Reports/YYYY-MM-DD.md`, written at the end of the working session.

# Daily report plan

**When:** at the end of each working session, and at least once per calendar day on which the studio worked. The orchestrator writes it; it is the last action before the session ends.

**Shape** (under 400 words):
1. One line: where the project stands (milestone, phase).
2. Done today: three to eight bullets, each with the seat and a commit or file.
3. Decisions made: link each `Decisions/` note created or changed.
4. Open for the CEO: the tie-breaks and requests, each with the studio's recommendation.
5. Next: what the studio does next session.
6. Risks and measurements: anything measured, anything that went red.

**Where the CEO reads it:** this folder in Obsidian, or on GitHub under `vault/Reports/`. Both are the same file.

**Automation:** a cloud routine can post a digest elsewhere later if the CEO wants one; the vault note stays the source.
