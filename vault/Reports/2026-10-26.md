# Daily report — 2026-10-26

**Where we stand.** Milestone M1 (browser client, authoritative headless server, one mod-defined unit). Design and plan passed both gates. 16 of 18 build tasks are done; the networking choice passed its spike gate. CI on `main` is green.

## Done overnight

- **M1 design** (`docs/superpowers/specs/2026-10-26-m1-foundation-design.md`). Five seats researched; gate 1 with five lenses failed revision 1 (rigour, mod-builder), passed revisions 2 and 3 after repairs. The biggest catch: the first design let the engine hard-code the default unit and ship the default package inside the client, a default-mod privilege the spec forbids.
- **M1 plan** (18 tasks). Gate 2: QA failed it, proving with models that two planted test defects stayed green and that parallel CI would flake. Repaired twice and re-gated.
- **Networking spike passed.** lightyear 0.31 over WebSocket is kept for M1. Measured on this machine: server tick p99 about 0.4 ms; a stalled client costs the server no memory; 127 bytes per tick for 1 unit and about 10.4 KB per tick for 1,000 units; a wasm client joins through headless Chrome in under 0.3 s. The spike also found a library-level message drop and the studio moved to a channel mode that keeps every message.
- **Code:** nine crates, about 9,600 lines, 140 tests passing. Every test was first seen red on a planted defect. Built: mod API and runtime with both packages (`base`, `acme`), simulation core, protocol, server boot and networking, client acquisition, join, resync and interpolation.
- **Bugs caught by our own tests:** a client test that could not detect extrapolation; error messages that leaked Rust type names to modders; empty unit ids accepted; a client that a duplicate player could block at the transport layer.
